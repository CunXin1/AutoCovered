# Covered Call Strike 研究框架(9 维决策法)

开仓流程第 3 步的执行手册;roll 选新腿同样适用,见文末「Roll 场景的适用性」。
delta 只回答"被叫走概率多大",不回答"这只股票**此刻值不值得**卖、
卖在**哪个价位之上**才不后悔"。以下 9 维逐一研究后合成决策。
(English edition: `strike-research.en.md`,内容与本文对应,改动时两版同步。)

**分工铁律**:机械层(delta 区间、OTM、DTE>30、覆盖率、net credit)
已由引擎和 propose 护栏强制执行,你不用也不许重新计算;研究层的工作是
**在确定性候选集内部选出该卖的那一档**。研究不能发明集外合约——护栏会拒绝。

**2026-10-02 起:开仓研究不再输出"卖/不卖"。** 运行 covered-call 就是要卖 call,
每个未覆盖仓位都要给出建议合约。九维投票只回答两件事:**strike 放多远、卖几张**。
("这轮不卖"的出口已取消 —— 原先它用于"权利金补不偿风险"的情形,现在这类情形
靠推远 strike 与减张消化,并在结论里如实写明代价。)

每一维:查什么 → 从哪查 → 怎么动决策(↑strike=更远/更安全,↓DTE=更短,
减张=部分覆盖)。所有维度只在这几个方向上投票,不投"不卖"。

---

## 1. IV 水位(卖得贵不贵)— 最重要的一维

- **查**:当前隐含波动率处于自身历史什么分位(IV Rank / IV Percentile)、
  IV 与已实现波动的比(IV/HV)。卖 covered call 本质是卖波动率,IV 低位卖 = 贱卖。
- **源**:`python -m src.data.market_context TICKER` —— 用 IBKR 自己的 IV 日线算,
  **禁止用 WebSearch 取 IV Rank**:各站算法与窗口不同,实测 2026-10-02 同一天
  IBM 第三方站给 11(→SKIP)而按 IBKR 序列算是 55(→积极卖),AAPL 三个站分别给
  6/37/43 —— 拿这种数字当决策阈值等于掷骰子。候选表的年化列是最终落地数字。
- **Rank 与百分位分歧时**:Rank 只看区间端点,百分位看整个分布。少数尖峰会把
  区间上端拉高、使 Rank 显得居中,此时**以百分位为准**(它回答的才是"今天贵不贵")。
  工具会在分歧 >15 点时打警告。
- **规则**:IVR < 20 → 这是在低波动里卖便宜,**↑strike 到候选集最远档 + 减张**,
  并在结论里写明"等 IV 回升能收更多"这笔机会成本;IVR 20–50 → 正常执行;
  IVR > 50(常见于事件前)→ 积极卖,可用同等权利金买到更远的 strike(↑strike)。

## 2. 财报与事件日历(炸点在哪)

- **查**:下一次财报日(务必复核,日期常改且各源不一)、产品发布/投资者日/
  指引更新;高 beta 股加查 FOMC/CPI 日期。
- **源**:positions.json 的 events 字段 + WebSearch 交叉验证。
- **规则**(2026-10-02 修订:**财报季不必跳过,改为按历史财报涨幅上提 strike**)。
  跨财报到期允许,引擎只在候选表打 ⚠️ 标记;"躲财报"也不再是默认偏好——
  10 月下旬这种财报密集窗口里,DTE>31 的合规新腿必然跨财报,躲不开,只能定价。
  执行顺序:

  1. **先拿历史事实**(必做,不许凭感觉估"适当增加多少"):
     `python -m src.data.earnings_moves TICKER --strike K1 --strike K2 [--price P]`
     输出该标的最近 N 次财报的反应日涨幅(收-收 与 盘中最高两种口径)、
     上行幅度分位,以及**每个候选 strike 的历史击穿率**
     (过去 N 次财报里有几次会打穿它)。
  2. **strike 下限**:strike 距现价 ≥ 历史**盘中上行涨幅的 p85**。
     用盘中口径而非收盘口径是保守选择:strike 被盘中触及即意味着当时已 ITM。
  3. **复核击穿率**:盘中口径历史击穿 **≤1 次且 ≤15% 样本** 才可用于跨财报开仓;
     超过就 ↑strike 到达标为止,或减张,或 SKIP。
  4. **样本不足**(有效财报 < 4 次,如新上市标的)→ 历史分布不可依赖:
     退回隐含 move,要求 strike 距离 ≥ 2× 隐含 move;候选集里没有这么远的档
     就取**最远档 + 减张**,并写明样本不足这件事。
  5. **财报日期未官宣**(各源打架)→ 视为整个窗口都有雷:取最远档 + 减张。

  仍然成立的披露义务:(a) 跨财报候选的权利金里含事件溢价,与同 delta 的
  财报前到期并列比较,多收的部分就是替 gap 风险收的保费,结论写明是否划算
  (两者现在**平等比较**,不再预设偏向财报前到期);(b) 历史分布不是概率保证——
  样本只有几次,且 IV 已经把市场预期波动定价进权利金,历史零击穿 ≠ 这次不破;
  (c) 被叫走情景必须落在结论里,低 delta ≠ 零概率。

## 3. 除息日(提前指派的暗门)

- **查**:expiry 前有没有 ex-dividend date;股息金额 vs 候选的时间价值。
- **源**:WebSearch「TICKER ex-dividend date」;positions.json events.ex_div。
- **规则**:除息在到期前且股息 > 届时预估时间价值 → 提前指派风险实质化,
  选**除息前到期**或 ↑strike 拉开距离(MSFT 这类分红股必查)。

## 4. 技术阻力位与 52 周高点(strike 放在墙后面)

- **查**:现价上方最近的强阻力:52 周高点、前高平台、大整数关口。
- **源**:`python -m src.data.market_context TICKER` 给 52 周高低点、距高点百分比、
  区间位置(全部由 IBKR 日线算出)。WebSearch 只用于补充"前高平台/整数关口"这类
  叙述性信息,禁止用它取 52 周高点这种能算的数字,也禁止自己画线编价位。
- **规则**:strike 尽量放在**强阻力之上**(墙帮你挡);候选 strike 恰好卡在
  前高下方一点 → 上移一档(那是磁铁位,最容易被打穿);
  股价刚创历史新高、上方无阻力 → 没有墙可借,↑strike 并减张。

## 5. 趋势状态(别在火车头前面卖票)

- **查**:近 1–3 个月是突破上行、区间震荡还是回落企稳;是否刚发生
  gap-up/业绩 beat 后的动量延续。
- **源**:`python -m src.data.market_context TICKER` 给 1/3/6 月涨幅与 52 周区间位置
  (确定性);WebSearch 只用于解释"为什么涨/跌"(财报、评级、产品、宏观)。
- **规则**:**强上升趋势 = covered call 最差的时机**(参考 roll 追不上暴涨的
  数学),→ **↑strike 到最远档 + 减张**,结论里写明被叫走情景;
  横盘震荡 = 最佳时机,正常区间内选;
  阴跌中 → 先核对维度 7 的成本价约束再说(权利金挡不住正股继续跌)。

## 6. 分析师目标价与已知催化剂(市场认为它能到哪)

- **查**:主流卖方一致目标价(中位数)、近 2 周有无密集上调评级、
  未来 1–2 个月已知催化剂(新品、大会、行业数据)。
- **源**:`python -m src.data.market_context TICKER` 给一致目标价、区间、覆盖家数、
  评级(yfinance 接口,IBKR 免费档不提供此项)。WebSearch 只用于补充"近两周有无
  密集上调/下调"与催化剂的叙述,禁止自行估计。
- **规则**:一致目标价比现价高 >20% 且候选 strike 低于目标价 → ↑strike 或减张;
  目标价密集下调/催化剂真空 → 可在区间内选偏近的 strike 多收权利金。

## 7. 成本价与税务(你自己的账,别人替代不了)

- **查**:strike 与持仓成本的关系;距长期资本利得天数;本批持仓的税务状态。
- **源**:positions.json 的 stock.avg_cost 与 metrics.days_to_long_term —— 唯一来源。
- **规则**(披露;2026-07-13 起由硬禁令放宽):strike ≤ avg_cost **允许**
  (水下回血模式),代价是结论里必须亮出**锁损账**:被叫走时每股锁损
  = avg_cost − strike − 累计已收权利金,写明净结果;同等权利金优先选能过
  维度 9 底线的最高 strike;水下票的维度 5(反弹风险)投票加权看待——
  反弹穿过低位 strike 会把浮亏变实亏;被叫走后若计划回补,提示 wash sale
  30 天窗口。days_to_long_term < DTE 且浮盈可观 → 被叫走会把长期税率变短期,
  ↑strike 或 SKIP 等过线;QCC(OTM+DTE>30)引擎已管。

## 8. 流动性(进得去还要出得来)

- **查**:候选合约的 bid/ask 点差、未平仓量。将来 roll/买回都要再过一次点差。
- **源**:候选表的 bid/ask 与点差% 列(确定性);OI 可 WebSearch 补充。
- **规则**:点差 > 10% → 换相邻 strike 或标准月度到期日(流动性最好);
  点差 > 20% → 该合约不碰。限价单一律挂 mid 附近,绝不市价。

## 9. 年化收益底线(这轮值不值得做)

- **查**:经过 1–8 维调整后,最终候选的年化收益率(候选表"年化"列)。
- **源**:候选表,唯一来源。
- **规则**:年化是**选档依据**,不再是否决线。超低 delta 下年化 < 4% 的档说明
  封顶风险换不回像样的钱 → 在候选集里换一档(通常是近一点的 strike 或更长 DTE)
  把年化拉回 4% 以上;若该标的全部候选都在 4% 以下(低波动股常见),
  就取年化最高的那一档并**在结论里显式写出"这笔权利金很薄"**,
  让用户知道自己在用多少上行空间换多少钱。

## 合成决策(固定程序)

1. 跑候选脚本拿确定性候选集(必要时两种 --style 各跑一次)。
2. 按上表逐维研究,每维给出:发现(一句话)+ 来源 + 投票
   (↑strike / ↓DTE / 减张 / 中性或有利)。
3. 合成:**点差 > 20% 的合约不碰**(换相邻 strike 或标准月度到期);
   strike ≤ 成本必须附维度 7 的锁损账,并优先换到成本线之上的档
   (注意 FIFO 按最早批次算,不是加权平均成本);
   **从候选集里选出满足最多 ↑strike 票的那一档**,DTE 取 31–45 为默认
   (theta 衰减最陡),除非维度 2/3 要求更短;
   ↑strike 票多且该标的可开多张时,同时减张。
4. 输出**决策表**(模板见下)+ 最终结论:(strike, expiry, contracts, 限价)
   + 反方观点(哪一维最可能让这个决定后悔)。**每个仓位都要有结论,
   没有"不卖"这个选项** —— 风险用 strike 距离和张数表达,不用弃权表达。
5. 用户确认后才走 propose CLI;你到决策表为止。

### 决策表模板

```
| # | 维度 | 发现 | 来源 | 投票 |
|---|------|------|------|------|
| 1 | IV 水位 | IVR 34,中位 | Barchart | 中性 |
| 2 | 财报 | 10/28,已避开 | 引擎+复核 | 中性 |
| ... |
结论:卖 <expiry> $<strike>C ×<n>,限价 <mid 附近>(年化 x.x%)
反方:若维度5的突破延续,strike 距离只有 +x%,两周内可能进 TESTED
代价:(若某维本来会投"不卖",在这里写明放弃了什么 —— 如"IV 在一年最低点,
等 IV 回升同距离能多收 X%")
```

## Roll 场景的适用性

roll 的新腿本质也是选合约,但不是 9 维全跑:

- **照常适用,逐维投票**:1(IV 水位 — IV 高位正是 roll 收 credit 的好时候)、
  2(财报 — roll 进财报窗口必须按本维度显式定价 gap 风险)、3(除息)、7(成本价与税务 —
  新 strike ≤ avg_cost 同样必须附锁损账)、8(流动性 — 旧腿买回 + 新腿卖出要过两次点差)、
  9(年化底线 — 对 net credit 年化设同样底线)
- **参考即可,不作否决**:4(阻力)、5(趋势)、6(目标价)— 被 test/breach 的仓位
  说明趋势已经在打你,这三维的信息价值主要在于判断"要 roll 多远"
- **合成时硬否决线**:点差 > 20%、年化 < 底线 → 该候选不合格;
  新 strike ≤ 成本需附维度 7 锁损账,并如实回答"这次 roll 是不是只是不想认输";
  候选集全军覆没时,结论就是买回或让股票被叫走,
  不要为了"必须 roll 出来"降低标准。
  (注:"默认都要卖"只适用于**开仓**;roll 场景仍然可以、也应该得出
  "不 roll,买回或让它被叫走"的结论 —— 那不是弃权,是三选项纪律。)

## 与系统其它部分的衔接

- **数字一律来自确定性脚本,WebSearch 只提供叙述**:
  价格/delta/年化/点差 ← 候选表(roll_candidates.py);
  历史财报涨幅与击穿率 ← `src.data.earnings_moves`;
  IV 分位 / 52 周高低点 / 各期涨幅 / 分析师目标价 ← `src.data.market_context`;
  历史收益 ← `src.stats`。
  WebSearch 的唯一职责是**叙述性事实**:为什么异动、有什么催化剂、核对财报日期、
  隐含 move 的量级。任何进入决策阈值的数字都不许来自 WebSearch —— 第三方站点
  对同一指标给出的值可以差 5 倍(见维度 1 的实测)。
- 研究结论必须落在候选集内;想要集外合约 = 回去改 --style 或改 config,
  不是绕护栏。
- 决策表全文写进**当次持仓报告的第三节**
  (`state/analysis/YYYY-MM-DD-positions-report.md`,骨架见
  `report-template.md`)。**不再按标的另存 `*-<TICKER>-open-research.md`** ——
  一次分析只产出一个文件。scheduled-tasks 推送手机时,正文取该节的决策表摘要。
